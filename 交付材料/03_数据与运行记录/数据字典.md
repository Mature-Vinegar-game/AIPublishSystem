# 05 数据字典（10 张表）

> 提交物③配套（数据结构与来源说明）[原文 L80]；口径唯一来源 `BUILD_SPEC.md` §3，字段名/类型/约束逐条对齐，改表须同步改本文件与 [04 数据处理与工具执行图](./04_数据处理与工具执行图.md) 并升版本号。
> 存储：SQLite（`data/app.db`），SQLAlchemy 2.x，**时间统一用 ISO8601 字符串**（如 `2026-11-01T20:30:00+08:00`），布尔用 `INTEGER 0/1`，JSON 用 `TEXT` 存紧凑 JSON 文本。
> 版本：`DD-v1.0`（基准日 2026-11-01）。

## 0 通用约定

| 约定 | 说明 |
|---|---|
| 主键 | 所有表 `id INTEGER PRIMARY KEY AUTOINCREMENT`（自增） |
| 编号 | 对外展示用业务编号：`task_no`、`material_no`、`rule_code`，均 `UNIQUE`；主键不对外当业务号 |
| 时间 | 服务端写入 ISO8601 字符串；`created_at` 必有，`updated_at` 仅任务表 |
| JSON 字段 | 命名以 `_json` 结尾，存对象/数组文本；读侧 `json.loads` 后校验，坏数据按空对象处理并记日志【设计】 |
| 软删除 | `materials.enabled`、`rules.enabled` 作为启用开关（0=停用）；**不做物理删除**，保证历史依据可回查 |
| 数据安全 | `password_hash`、`salt` 不可出现在任何接口响应；`LLM_API_KEY` 不入库，只在 `.env` |

## 1 表关系总览

```
users 1 ──< business_tasks.created_by
users 1 ──< ai_tasks.created_by / result_versions.created_by
users 1 ──< review_records.reviewer_id
business_tasks 1 ──< task_materials >── 1 materials
business_tasks 1 ──< ai_tasks 1 ──< tool_call_records
business_tasks 1 ──< ai_results（经 ai_tasks）
business_tasks 1 ──< result_versions 1 ──< review_records.version_id
rules（独立主数据，被工具读取，不建外键）
```

- 10 张表：`users`、`business_tasks`、`materials`、`task_materials`、`rules`、`ai_tasks`、`tool_call_records`、`ai_results`、`result_versions`、`review_records`。
- 外键关系以 `business_task_id` 为总线，跨表 JOIN 不需要中间映射表 [原文 L49]。
- `rules` 与 `materials` 是主数据，工具按 `rule_code`/`material_no` 读取；不设物理外键，避免历史依据因主数据停用而断裂（软停用 + 版本化）【设计】。

## 2 `users` 账号表

用途：登录与角色判定（`operator` 印制业务操作员 / `reviewer` 印制成本审核员）。来源：`seed/seed_demo.py` 幂等创建两个账号。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 用户主键 | 系统 | `1` |
| `username` | TEXT | UNIQUE、非空 | 登录名 | 种子 | `operator` |
| `password_hash` | TEXT | 非空 | `pbkdf2_hmac('sha256', pwd, salt, 100000)` 十六进制 | 种子/系统 | `9f2c…`（64 字符 hex） |
| `salt` | TEXT | 非空 | 随机盐（hex） | 种子/系统 | `3a7d…` |
| `role_code` | TEXT | 非空、枚举 | 角色码：`operator` / `reviewer` | 种子 | `reviewer` |
| `display_name` | TEXT | 非空 | 展示名（演示用化名） | 种子 | `李静` |
| `created_at` | TEXT | 非空 | 创建时间 ISO8601 | 系统 | `2026-11-01T20:30:00+08:00` |

- 约束补充：一个 username 只能一个角色；不存明文密码、不存 token；cookie 签名密钥在 `.env` 的 `SECRET_KEY`。
- 数据量：演示固定 2 行。

## 3 `business_tasks` 业务任务表

用途：印制任务主表，承载目标、11 项参数、四态与乐观锁版本。来源：operator 通过 `POST /api/business-tasks` 创建，页面 `task_new.html`。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 任务主键，全链路 `business_task_id` | 系统 | `1` |
| `task_no` | TEXT | UNIQUE、非空 | 业务任务号（对外展示） | 系统生成 | `BT-DEMO-0001` |
| `business_type` | TEXT | 非空、默认 `print_cost` | 业务类型（本系统仅印制成本测算） | 系统 | `print_cost` |
| `title` | TEXT | 非空、≤100 | 任务名称 | 表单必填 | `《XX 年鉴》16 开 3000 册成本测算` |
| `goal` | TEXT | 非空、≤500 | 业务目标（要解决什么） | 表单必填 | `核算单册成本并给出依据` |
| `params_json` | TEXT | 非空、JSON | 印制参数：`format/print_sheet/qty/paper_type/binding/color_pages/process/book_title/note` | 表单/`PUT` | `{"format":"16开","print_sheet":12,"qty":3000,"paper_type":"胶版纸80g","binding":"胶装","color_pages":4,"process":"覆膜"}` |
| `status` | TEXT | 非空、枚举 | `PENDING` 待处理 / `PENDING_REVIEW` 待审核 / `REJECTED` 退回 / `COMPLETED` 完成 | 状态机 | `PENDING` |
| `revision` | INTEGER | 非空、默认 1 | 乐观锁版本；`PUT` 带 `expected_revision`，不符 409 | 系统自增 | `3` |
| `created_by` | INTEGER | 非空、FK→`users.id` | 创建人（operator） | 会话 | `1` |
| `created_at` | TEXT | 非空 | 创建时间 | 系统 | `2026-11-01T20:31:00+08:00` |
| `updated_at` | TEXT | 非空 | 最后更新时间 | 系统 | `2026-11-01T20:45:00+08:00` |

- 状态迁移见 [01 需求与设计说明](./01_需求与设计说明.md) §3.2；`PENDING/REJECTED` 可改，`PENDING_REVIEW/COMPLETED` 冻结（改 → 409）。
- `revision` 用途：防"两人同时改参数"互相覆盖；不用于结果版本（结果版本在 `result_versions`）。

## 4 `materials` 资料表（纸张/工艺/装订/费率/书目）

用途：报价与资料主数据，工具的检索对象，也是依据（`material_no`）来源。来源：`seed/paper_quotes.json`（18 种纸）、`process_quotes.json`（6 项工艺 + 5 项装订 + 1 项费率）、`seed_demo.py`、页面 `materials.html` 新增。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 资料主键 | 系统 | `3` |
| `material_no` | TEXT | 非空；与 `version_no` 组合 UNIQUE | 资料编号，工具 `source.ids` 与 `basis_refs.id` 用它；同编号多条 = 多版本 | 系统生成 | `PAPER-001` |
| `type` | TEXT | 非空、枚举 | `paper` / `process` / `binding` / `rate` / `book` | 表单 | `paper` |
| `title` | TEXT | 非空 | 资料名称 | 表单 | `胶版纸80g` |
| `source` | TEXT | 非空 | 来源（自编/公开/获准使用 + 日期），演示数据标"教学模拟" | 表单 | `教学模拟报价（自编）` |
| `version_no` | INTEGER | 非空、默认 1 | 资料版本号；同 `material_no` 多版本可查 | 系统/表单 | `2` |
| `content_json` | TEXT | 非空、JSON | 按 `type` 不同结构（见下表） | 表单 | `{"price_per_ream":265,"grammage":80,"format_fit":["16开","32开"]}` |
| `enabled` | INTEGER | 非空、默认 1 | 1 启用 / 0 停用（停用后依据校验软标记"依据已变更"） | 表单 | `1` |
| `created_at` | TEXT | 非空 | 创建时间 | 系统 | `2026-11-01T20:20:00+08:00` |

**`content_json` 按类型的最小必需键（工具读取口径）**

| `type` | 必需键 | 含义 | 被谁读 |
|---|---|---|---|
| `paper` | `price_per_ream`（元/令）、`grammage`（g/m²）、`format_fit[]` | 纸张单价、克重、可适配开本 | `calculate_cost` 纸张费、`validate_spec` 纸张-开本适配 |
| `rate` | `price_per_1000_sheets_per_color`（元/千印张/色）、`plate_fee_per_color`（元/色，默认 80）【设计】 | 印刷费率、制版费率 | `calculate_cost` 印刷费/制版费 |
| `binding` | `price_per_1000`（元/千册） | 装订单价 | `calculate_cost` 装订费 |
| `process` | `price_per_1000`（元/千册） | 工艺单价（覆膜/UV/烫金） | `calculate_cost` 工艺费 |
| `book` | `book_no`、`title`、`format`、`print_sheet` | 书目标样（用于示例任务/校验参考） | `search_quotes` |

- 缺任一必需键 → `calculate_cost` 返回 `ok=false, DATA_NOT_FOUND, data.missing[]`，**不得用默认值编造单价**。
- 约束补充：唯一约束为 `UNIQUE(material_no, version_no)`，用于支持同一报价的版本化（`BUILD_SPEC.md` §3 简写为 `material_no UNIQUE`，以实现为准）【实现】；停用（`enabled=0`）不删除历史，保证依据可回查。
- `source` 必须可说明出处；页面角标"模拟数据·仅教学演示" [原文 L61]。

## 5 `task_materials` 任务-资料关联表

用途：把报价资料挂到任务上，构成"任务关联资料"集合，参与 `basis_refs` 校验的合法 id 范围。来源：任务详情页"关联资料"按钮（种子示例任务关联 `PAPER-001`）。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 关联主键 | 系统 | `12` |
| `task_id` | INTEGER | 非空、FK→`business_tasks.id` | 业务任务 ID（等价 `business_task_id`） | 页面/API | `1` |
| `material_id` | INTEGER | 非空、FK→`materials.id` | 资料 ID | 页面/API | `3` |
| `link_role` | TEXT | 非空、默认 `related` | 关联用途：`paper` 纸张报价（种子使用）/ `related` 默认；预留 `rule_ref` 规则参考、`sample` 书目标样 | 表单 | `paper` |
| `created_at` | TEXT | 非空 | 关联时间 | 系统 | `2026-11-01T20:33:00+08:00` |

- 约束：`UNIQUE(task_id, material_id)` 防重复关联，重复关联按幂等返回已存在记录【实现】。
- 关联资料不是"AI 运行必需"，但会进入 `input_snapshot_json` 的关联资料摘要，并在依据校验中作为合法 id 来源。

## 7 `ai_tasks` AI 任务表

用途：一次 AI 运行实例（重试即新实例），承载状态、模型模式、输入快照与计数。来源：`POST /api/business-tasks/{id}/ai-tasks` 与 `/retry`。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | AI 任务主键 `ai_task_id` | 系统 | `7` |
| `business_task_id` | INTEGER | 非空、FK | 关联业务任务（同一 task_id 总线） | API | `1` |
| `status` | TEXT | 非空、枚举 | `PENDING` / `RUNNING` / `SUCCEEDED` / `FAILED` | 执行器 | `RUNNING` |
| `model_mode` | TEXT | 非空 | `real` / `mock`（记录当次模式，页面标注） | 配置快照 | `real` |
| `model_name` | TEXT | 可空 | 模型名（如 `deepseek-chat`） | `.env` 快照 | `deepseek-chat` |
| `input_snapshot_json` | TEXT | 非空、JSON | 输入快照：参数、关联资料摘要、规则摘要、提示词版本 | API 创建时 | `{"params":{…},"materials":["PAPER-001"],"rules":["RULE-QTY-004"]}` |
| `counters_json` | TEXT | 可空、JSON | 计数：`rounds` / `tool_calls` / `distinct_types` / `model_calls` | 执行器 | `{"rounds":4,"tool_calls":3,"distinct_types":3,"model_calls":4}` |
| `error_code` | TEXT | 可空 | 失败码：`TOOL_TIMEOUT` / `TOOL_ARGS_INVALID` / `MODEL_ERROR` / `NO_TOOL_CALL` / `DATA_FABRICATED` / `STALE_RUNNING` | 执行器 | `TOOL_TIMEOUT` |
| `error_message` | TEXT | 可空 | 人类可读错误说明（≤500，不泄露 key/入参密钥） | 执行器 | `工具 search_quotes 执行超时（3000ms）` |
| `started_at` | TEXT | 可空 | 开始执行时间 | 执行器 | `2026-11-01T20:40:02+08:00` |
| `finished_at` | TEXT | 可空 | 终态时间 | 执行器 | `2026-11-01T20:40:36+08:00` |
| `created_by` | INTEGER | 非空、FK→`users.id` | 触发人（operator） | 会话 | `1` |
| `created_at` | TEXT | 非空 | 创建时间 | 系统 | `2026-11-01T20:40:00+08:00` |

- 终态兜底：进程启动时把残留 `RUNNING` 清理为 `FAILED(STALE_RUNNING)`；`finished_at` 必须落，避免"永久运行中"。
- 重试：`POST /ai-tasks/{id}/retry` 仅对 `FAILED` 生效，新建一行 `ai_tasks`（同 `business_task_id`），旧行保留；受 `MAX_AI_RUNS=10` 限制（超限 429）。

## 8 `tool_call_records` 工具调用记录表

用途：Agent 每次工具调用一条记录，是"真实调用"的核心证据 [表2 L31]。来源：执行器写入，前端只读。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 记录主键 | 执行器 | `31` |
| `ai_task_id` | INTEGER | 非空、FK→`ai_tasks.id` | 所属 AI 运行（重试后仍可分辨） | 执行器 | `7` |
| `business_task_id` | INTEGER | 非空、FK | 业务任务 ID（与结果同一 ID） | 执行器 | `1` |
| `seq` | INTEGER | 非空 | 任务内调用序号，从 1 递增（展示"连续调用顺序"） | 执行器 | `3` |
| `tool_name` | TEXT | 非空、枚举 | `search_quotes` / `get_rules` / `validate_spec` / `calculate_cost` | 模型选择 | `calculate_cost` |
| `tool_type` | TEXT | 非空、枚举 | `retrieval` / `validation` / `calculation` | 工具注册表 | `calculation` |
| `args_json` | TEXT | 非空、JSON | 模型给出的参数原文（校验前），用于复现与审计 | 模型 | `{"params":{"qty":3000,"print_sheet":12}}` |
| `result_summary` | TEXT | 可空、≤200 字 | 结果摘要（成功摘要/失败原因），不存全文 | 执行器 | `总成本 14638.00 元，单册 4.88 元，5 项 line_items` |
| `source_ids_json` | TEXT | 可空、JSON | 本次结果的数据来源 ID 数组（`material_no` / `rule_code`），依据校验锚点 | 工具 | `["PAPER-001","RULE-QTY-004"]` |
| `status` | TEXT | 非空、枚举 | `SUCCESS` 成功 / `FAILED` 失败 / `SKIPPED` 跳过（重复同参调用或超限未执行） | 执行器 | `SUCCESS` |
| `error_code` | TEXT | 可空 | `TOOL_TIMEOUT` / `TOOL_ARGS_INVALID` / `DATA_NOT_FOUND` / `TOOL_EXEC_ERROR` | 执行器 | `TOOL_ARGS_INVALID` |
| `latency_ms` | INTEGER | 可空 | 实际耗时（毫秒），用于对照 3000ms 限额 | 执行器 | `128` |
| `created_at` | TEXT | 非空 | 写入时间 | 系统 | `2026-11-01T20:40:12+08:00` |

- 失败调用**也必须落一条**（`status=FAILED` + `error_code`），不允许"失败不记录"或"失败记成功"。
- 页面展示全字段；`args_json` 与 `source_ids_json` 可展开，用于依据三跳第 3 跳。

## 9 `ai_results` AI 结果表

用途：一次成功运行的产出与依据，供结果页展示与依据校验；不直接代表"可提交版本"。来源：执行器成功终态写入。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 结果主键 `result_id` | 执行器 | `7` |
| `ai_task_id` | INTEGER | 非空、FK | 产出它的 AI 运行 | 执行器 | `7` |
| `business_task_id` | INTEGER | 非空、FK | 业务任务 ID | 执行器 | `1` |
| `content_md` | TEXT | 非空 | 中文 Markdown 测算说明（含公式、结论、依据） | 模型 final | `## 测算结论…` |
| `structured_json` | TEXT | 非空、JSON | 结构化结果：`line_items[]`、`total`、`per_copy`、`missing[]`、`uncertain[]`、`valid` | 模型 final | `{"total":14638.0,"per_copy":4.88,"line_items":[…],"missing":[]}` |
| `basis_refs_json` | TEXT | 可空、JSON | 依据数组 `[{type:'material'/'rule'/'calc', id, label}]` | 模型 final + 校验 | `[{"type":"material","id":"PAPER-001","label":"胶版纸80g"}]` |
| `basis_ok` | INTEGER | 非空、默认 0 | 依据校验结果：1 通过 / 0 不通过（不通过 → 标"依据不一致"，阻止确认） | 校验器 | `1` |
| `uncertain_items_json` | TEXT | 可空、JSON | 不确定项说明（口径假设、低置信、依据缺失） | 模型 + 校验器 | `["制版费按 80 元/色演示参数"]` |
| `missing_data_json` | TEXT | 可空、JSON | 缺失数据清单（缺哪个单价/规则） | 工具 + 模型 | `["缺少 binding 单价"]` |
| `created_at` | TEXT | 非空 | 写入时间 | 系统 | `2026-11-01T20:40:35+08:00` |

- 重跑 AI **只新增** `ai_results`，不自动生成版本；只有"采用/保存结果"才写 `result_versions`。
- 数据不足仍输出 `total` → 判 `DATA_FABRICATED`，此时**不写** `ai_results`（避免不可用结果进入版本）。

## 10 `result_versions` 结果版本表

用途：可查版本（AI 原始/人工修改/审核通过），只增不改，≥2 版可查 [表2 L32]。来源：`POST /api/business-tasks/{id}/results`（`source=MANUAL` 或采用 AI 结果生成 `AI` 版本）。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 版本主键 `version_id` | 系统 | `2` |
| `business_task_id` | INTEGER | 非空、FK | 业务任务 ID | API | `1` |
| `version_no` | INTEGER | 非空；与 `business_task_id` 组合 UNIQUE | 版本号，从 1 递增 | 服务层生成 | `2` |
| `source` | TEXT | 非空、枚举 | `AI`（采用 AI 结果）/ `MANUAL`（人工修改） | API | `MANUAL` |
| `content_md` | TEXT | 非空 | 版本正文（可编辑后保存） | 表单 | `## 测算结论（人工核减装订费）…` |
| `structured_json` | TEXT | 可空、JSON | 版本结构化数据（金额/明细），供对比与复算 | 表单/采纳 | `{"total":14600.0,"per_copy":4.87,…}` |
| `basis_refs_json` | TEXT | 可空、JSON | 该版本依据（沿用或人工补充） | 表单/采纳 | 同上 |
| `change_note` | TEXT | 可空、≤500 | 变更说明（人工修改必填【建议】） | 表单 | `装订单价按新报价调整为 60 元/千册` |
| `created_by` | INTEGER | 非空、FK→`users.id` | 操作人（审核人与时间可追溯） | 会话 | `1` |
| `created_at` | TEXT | 非空 | 创建时间 | 系统 | `2026-11-01T20:50:00+08:00` |

**约束与规则**

- `UNIQUE(business_task_id, version_no)` —— `BUILD_SPEC.md` §3 写作 `UNIQUE(task_id,version_no)`，本表列名为 `business_task_id`，语义相同。
- 只增不改：已提交/已通过版本的任何修改 → 409（版本冻结）；修改 = 新增一版。
- 至少 2 版可查：AI 采纳版 + 人工修改版，或 退回前版 + 重提版。

## 11 `review_records` 审核记录表

用途：审核流水（通过/退回 + 意见 + 审核人 + 时间），支撑"操作人/时间/意见"三字段与退回重提闭环 [表2 L32]。来源：`POST /api/business-tasks/{id}/review`（reviewer）。

| 字段 | 类型 | 约束 | 含义 | 写入方/来源 | 示例 |
|---|---|---|---|---|---|
| `id` | INTEGER | PK 自增 | 审核流水主键 | 系统 | `3` |
| `business_task_id` | INTEGER | 非空、FK | 业务任务 ID | API | `1` |
| `version_id` | INTEGER | 可空、FK→`result_versions.id` | 被审核的版本（正常审核必填；字段可空以兼容历史数据） | API | `2` |
| `action` | TEXT | 非空、枚举 | `APPROVE` 通过 / `REJECT` 退回 | 审核表单 | `REJECT` |
| `opinion` | TEXT | 退回时必填 | 审核意见 | 审核表单 | `装订费单价与报价单版本不一致，请复核` |
| `reviewer_id` | INTEGER | 非空、FK→`users.id` | 审核人（必须是 reviewer） | 会话 | `2` |
| `created_at` | TEXT | 非空 | 审核时间（服务端时间） | 系统 | `2026-11-01T21:05:00+08:00` |

- 一次审核动作一条记录；同版本重复审核按 409 或幂等处理（见 [06 测试用例](./06_测试用例.md) TC08），不得产生两条通过记录。
- 通过回写 `business_tasks.status=COMPLETED`；退回回写 `REJECTED`，任务可修改后重提。

## 0 判定与填写规则

| 规则 | 说明 |
|---|---|
| 预期可判定 | 每条预期必须落到**状态值 / 页面文案 / HTTP 状态码 / 错误码 / 具体数值**，禁止写"正常""成功即可" |
| 实际结果 | 执行前填"—（待执行）"；执行后填 `PASS` 或 `FAIL + 实际现象` |
| 缺陷编号 | FAIL 时填 `BUG-00x`，与 [07 缺陷与回归记录](./07_缺陷与回归记录.md) 台账同号；PASS 填 `—` |
| 回归结果 | 缺陷修复后重跑本用例：`REGRESSION-PASS` / `REGRESSION-FAIL` |
| 证据 | 每 FAIL 至少留 1 张截图 + 对应请求/响应；证据路径写进执行记录表 |
| 环境 | 统一 `APP_ENV=demo`、`LLM_MODE=real`、单进程 `127.0.0.1:8000`、数据库 `data/app.db` |

### 2.3 故障注入的两种触发路径（步骤里优先用页面）

| 路径 | 说明 |

```
                              └──────── 回归失败则重开并降级 ────────────┘
```

- 每条缺陷至少绑定 1 条回归用例；每条用例 FAIL 必须能追到缺陷编号，不允许"执行了但没记录"。
- 未关闭缺陷进入"未解决问题清单"并写明影响范围（与 [07 缺陷与回归记录](./07_缺陷与回归记录.md) 第 4 节一致）。

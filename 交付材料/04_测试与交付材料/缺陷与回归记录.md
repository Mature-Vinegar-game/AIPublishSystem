## 5 缺陷处理流程（与用例/版本闭环）

```
执行用例 → 发现异常 → 立即登记（日期/用例/现象/复现步骤/严重级）
        → 分级分配 → 修复（提交代码 + 记录修复版本/tag）
        → 回归（绑定同一 tag 重跑用例）→ 通过则关闭；不通过则重开
        → 挂起/不修 → 进"未解决问题清单" → 演示话术与规避方案同步更新
```

对照关系（提交前自检）：

| 检查 | 通过标准 |
|---|---|
| 用例 ↔ 缺陷 | 每条 FAIL 用例都有缺陷编号；每条缺陷都能找到发现用例 |
| 缺陷 ↔ 回归 | 每条关闭缺陷至少有 1 条回归记录，且回归绑定版本/tag |
| 缺陷 ↔ 演示 | 未关闭缺陷与"未解决问题清单"、PPT 风险页、录屏话术三处一致 |
| 缺陷 ↔ 材料 | 缺陷台账日期落在开发记录时间线内，不与分工记录矛盾 [原文 L82] |

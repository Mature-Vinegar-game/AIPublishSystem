## 第 1 页 · 封面

**标题**：印制参数校验与成本测算 AI 系统
**副标题**：第 __ 组 ｜ 业务方向：印制 ｜ 11/06 验收

- 一句话定位：把"查报价 → 核规格 → 算五项成本 → 主管复核"做成可追溯、可复算、可审核的单体 Web 系统。
- 关键数字：4 个工具 / 3 类 / 23 接口 / 10 表 / 12 条用例 / 2 类角色。
- 底部小字：模型 OpenAI 兼容接口（`LLM_MODE=real`）｜数据为教学模拟。

**建议截图**：系统登录页（深蓝主色 + 演示账号提示）。

**讲解要点**：先说"我们只做印制一个方向"，避免教师误以为覆盖出版全流程 [原文 L3]。

## 第 2 页 · 场景与角色

**标题**：谁在什么场景解决什么问题

- 场景：一本 16 开、3000 册、四色（彩色页 4）、胶装的书要报价——业务员录参数，AI 调工具出测算单。
- 角色 1 印制业务操作员（`operator`）：建任务、跑 AI、改结果、提交审核。
- 角色 2 印制成本审核员（`reviewer`）：复核依据与金额，通过或退回；**不能建任务、不能跑 AI**。
- 权限落点：401 未登录 / 403 角色不足 / 404 对象不属于本人，全部后端校验。

**建议截图**：两个浏览器并排登录（左 operator 菜单含"新建任务"，右 reviewer 无该按钮）。

**讲解要点**：强调"不是前端隐藏按钮，接口层同样拒绝" [表2 L27]。

## 第 3 页 · 主流程 7 环节

**标题**：7 个环节，每环节都有页面与接口

| # | 环节 | 页面/接口 |
|---|---|---|
| ① | 创建任务 | `task_new.html` → `POST /api/business-tasks` |
| ② | 填写需求/导入数据 | 11 项参数 + 关联资料 `task_materials` |
| ③ | 调用工具处理 | "运行 AI 测算" → 4 工具 / 3 类自动选择 |
| ④ | 查看结果和依据 | 测算说明 + 明细表 + 依据三跳 + 执行记录 |
| ⑤ | 人工修改或确认 | 保存人工版本 `result_versions(MANUAL)` |
| ⑥ | 审核 | 提交 → 通过/退回（意见必填） |
| ⑦ | 查询历史记录 | 版本列表 + 按状态筛选 + 同一 `task_id` 回查 |

**建议截图**：任务详情页整页（左上任务信息、中部 AI 运行区、下部结果/版本/审核），用箭头标 ①-⑦。

**讲解要点**：一句话过每个环节，"环节之间不换页面、不换任务 ID"。

## 第 4 页 · 架构与工具链

**标题**：单体 + 单进程 + 一个模型接口

- 浏览器 → uvicorn `:8000` 单进程（Jinja2 + 23 个 REST 接口）→ 服务层 → Agent 循环 → 工具层 / LLM → SQLite。
- 4 个工具 3 类：`search_quotes`/`get_rules`（retrieval）、`validate_spec`（validation）、`calculate_cost`（calculation）。
- 限额：工具 ≤6 次、模型 ≤8 轮、单次模型 30s、单次工具 3000ms、整体 90s、重试 ≤10 次。
- 不做：OCR/PDF 解析、微服务、多 Agent、消息队列、Docker。

**建议截图**：[03 技术调用图](./03_技术调用图.md) 导出图（`ARCH-v1.0`），与页脚限额实拍并列。

**讲解要点**：用图 2 说明"为什么能 15 分钟冷启动"，顺带回应"有没有微服务"的追问。

## 第 5 页 · 真实调用证据（先亮不可替代分）

**标题**：真实模型 + 真实工具 + 真实记录

- 第一屏：`/system` 系统信息页——`llm_mode=real`、模型名、`key_configured=true`、系统时间。
- 第二屏：任务详情执行记录——`seq` 连续、≥2 类工具、每次含参数/结果摘要/来源 ID/耗时/状态。
- 第三屏：`app.db` 同一 `business_task_id` 关联 `ai_tasks`/`tool_call_records`/`ai_results`（可现场 SQL 查）。
- 口径：**mock 不作为验收兜底**，失败也照实显示错误码。

**建议截图**：系统信息页 + 执行记录表（含一条 `FAILED` 记录更可信）+ `/system/meta` 返回 JSON。

**讲解要点**：这一步不放 PPT 动画，直接切系统；PPT 只留证据截图作断网备用 [原文 L63]。

## 第 6 页 · 结果依据三跳

**标题**：结果里的每个数字，都能点回来源

- 第 1 跳：结果依据列表 `basis_refs[]`（`material_no` / `rule_code` / `calc`）。
- 第 2 跳：点开资料/规则详情——来源、版本、单价、规则内容。
- 第 3 跳：执行记录里该次调用的 `args_json` 与 `source_ids_json`，证明"本次取到"。
- 校验：`basis_refs` 不命中 → `basis_ok=0` + "依据不一致"，提交被拒（409）。

**建议截图**：三张并排截图（结果依据 → 资料详情 → 执行记录），用编号箭头连起来。

**讲解要点**：现场抽一条依据走一遍；被问"为什么是 14638"时回第 3 页的公式与复算。

## 第 7 页 · 人工确认与两版本

**标题**：改得动、退得回、查得到

- 修改：AI 结果采纳后人工改金额，保存即生成 `v2 / MANUAL`，填写变更说明。
- 审核：提交 → `PENDING_REVIEW` 冻结 → reviewer 退回（意见必填）→ 重提 → 通过 `COMPLETED`。
- 版本：v1（AI 原始 14638.00）/ v2（人工 14600.00）均可切换查看，操作人/时间/意见齐全。
- 越权：operator 调审核接口 → 403；访问他人任务 → 404。

**建议截图**：版本列表（两行不同来源）+ 审核意见 + 一条 403 响应。

**讲解要点**：现场演示"退回后再提交"，这是教师最常抽查的闭环 [表4 L57]。

## 第 8 页 · 测试与缺陷

**标题**：12 条用例覆盖 9 类，缺陷闭环可查

- 覆盖：正常 / 必填缺失 / 数据不足 / 工具参数错误 / 超时 / 依据不一致 / 越权 / 重复提交 / 版本查询 + 业务专项（成本复算、规格校验）+ 失败重试不丢修改。
- 关键证据：TC11 手工复算 14638.00 / 4.88 与页面一致；TC07 三条越权 403/404 请求卡。
- 缺陷：`BUG-00x` 台账 → 修复版本/tag → 回归用例 → 关闭；未关闭进"未解决问题清单"。
- 核对：`CHK-01~04` 由非开发成员/互测组签字。

**建议截图**：[06 测试用例](./06_测试用例.md) 覆盖矩阵表 + [07 缺陷与回归记录](./07_缺陷与回归记录.md) 一条"修复→回归"闭环行。

**讲解要点**：只讲"哪一类最容易翻车、我们怎么证明它没问题"，不逐条念用例。

## 第 9 页 · 演示分工与风险兜底

**标题**：谁讲什么，断了怎么办

- 分工：主讲（流程与依据）/ 操作手（建任务、跑 AI、切版本）/ 记录手（截图、计时、递请求卡）。
- 兜底 1：断网 → 播备用录屏（真实运行、不剪辑、开头含 `/system` 与系统时间）。
- 兜底 2：模型报错 → 展示 `FAILED` + 错误码 + 重试，恰好演示"异常处理"。
- 兜底 3：教师临时换参数 → 现场改纸张/印数重跑，结果与依据随之变化。

**建议截图**：演示分工表 + 备用录屏文件名 + 故障注入入口。

**讲解要点**：把"会失败"讲成设计的一部分 [表4 L56]，但绝不能出现"假成功"。

## 12 常见追问与应答（备用口述）

| 追问 | 应答 |
|---|---|
| "结果是不是模型编的？" | 打开执行记录 `source_ids_json` 与依据三跳，指出同一 `task_id` 的调用序号 |
| "换参数为什么结果变了？" | 现改印数重跑，对比两次 `args_json` 与 `line_items.formula` |
| "数据不够会怎样？" | 缺数据任务如实报缺，`total=null`，`missing_data` 列出缺失单价，不输出金额 |
| "失败了呢？" | 展示 `FAILED`+`TOOL_TIMEOUT`，重试生成新 `ai_task_id`，人工版本仍在 |
| "能改数据库绕过审核吗？" | 不能：审核走接口、角色/状态双校验；越权请求现场演示 403/404 |
